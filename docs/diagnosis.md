# 诊断记录与验证边界

## 观察到的现象

2026-10-02，一台 Apple Silicon Mac 上的 Steam Civ V 1.4.2 在安装中文补丁前曾成功进入游戏，安装后开始在启动阶段退出。机器运行 macOS 26.5.1。

本机日志出现过以下短错误：

```text
Languages table not found or is empty
Failed to Load database
Failed to Save database
```

汇总语言数据库曾为零字节。上述是失败表现，并非已确定的根本原因。

## 排查经过

1. 检查汉化文件、语言设置与数据库；尝试离线重建缓存，未恢复正常启动。
2. 回退补丁涉及的 154 个文件：6 个覆盖文件按备份恢复，148 个新增文件移除。回退后的英文状态仍退出。
3. 通过 Steam 验证游戏文件；校验日志结束状态为 `No Error`，没有观察到重新下载。使用全新用户配置仍失败。
4. 对比重新生成的本体、资料片和其他语言数据库：除汇总库外，多项与安装前备份逐字节一致。
5. 从 `Contents/MacOS` 直接调用原版游戏执行文件，仅在子进程移除 `DYLD_INSERT_LIBRARIES`，并设置 Steam 游戏标识。用户确认英文成功运行，输出记录显示正常退出。
6. 恢复中文补丁，沿用同一入口。用户确认中文正常，快速开始后进入实际对局；该次进程正常退出。

原始完整日志、账号标识、用户名、机器路径、游戏数据库、存档和字体均不在此仓库内。

## 可以得出的结论

这个启动方式在上述机器上同时支持原版英文和已安装中文补丁的游戏。它是一项有实际验证记录的启动替代方案。

## 尚不能得出的结论

- 没有单独验证“只绕过启动器”和“只移除注入库”，不能确定是哪项改变起作用。
- 不能仅由安装前后顺序认定中文翻译或字体就是根因。
- 没有证明 Steam 游戏库中的原启动按钮已经恢复。
- 未验证其他 Mac、其他系统版本、多人联机、Steam 叠加层或长时间稳定性。
- 此仓库的通用 Python 入口尚未单独做真实游戏回归；实机通过的是重构前、行为相同的定制脚本。

## 报告问题

请描述系统版本、Intel/Apple Silicon、游戏版本、是否安装补丁，以及失败发生在主菜单前还是对局中。可以先运行 `python3 launch.py --dry-run` 检查路径。

日志保存在用户自己的 Library/Logs 目录，可能包含 Steam 账号数字标识或个人路径。提交 issue 前手动去除这些内容，只提供必要错误片段。不要直接上传完整日志、崩溃报告或备份。
